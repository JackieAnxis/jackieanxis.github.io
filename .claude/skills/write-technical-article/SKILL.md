# 技术原理文章写作流程

> 从源码和文档中提炼原理，写成面向程序员的技术文章。不讲操作，不贴代码，只讲「为什么」和「怎么运作」。

## 适用场景

- agent-revelations 电子书的章节写作（默认场景）
- 任何「阅读源码/文档 → 输出技术原理文章」的写作任务

## 写作原则

这些原则在动手之前就应该明确，贯穿整个写作过程：

1. **只讲原理，不讲操作**：读者可以看官方文档了解"怎么用"，文章的职责是解释"为什么这样设计"和"底层怎么运作的"
2. **禁止直接引用代码**：读者没有读过源码，贴代码会让他们迷失。用伪代码、架构图、流程图、ASCII 示意来表达逻辑
3. **用类比建立直觉**：在深入技术细节前，先用读者熟悉的场景建立心智模型
4. **从"为什么"到"怎么做"**：先解释问题（为什么需要这个机制），再解释方案（怎么实现的），最后解释后果（实现后会怎样）
5. **语言自然流畅**：不是学术论文，也不是博客随笔，是"一个资深程序员给同行讲原理"的语气

## 写作流程

### 第 1 步：明确写作范围

与用户确认：

- **主题**：这一章讲什么？（如"上下文压缩"、"工具系统"、"权限管线"）
- **目标读者**：读者已经知道什么？需要什么前置知识？
- **已有章节**：查看同目录下已有的文章，避免重复，确定这一章的边界
- **关联章节**：哪些内容属于其他章节？在文中用链接指向，不展开

如果用户指定了源码路径或文档路径，记录下来。

### 第 2 步：收集素材

这一步是纯研究，不写文章。

**源码研究**（如果适用）：
- 用 Explore 子代理搜索源码中与主题相关的文件
- 重点找到：核心数据结构、关键函数、配置常量、触发条件、处理流程
- 记录关键常量值（阈值、上限、默认值），这些是验证准确性的锚点

**文档研究**（如果适用）：
- 阅读官方文档中与主题相关的页面
- 关注：概念解释、架构图、设计决策、边界条件

**已有文章研究**：
- 阅读同目录下已有的章节，理解写作风格和术语体系
- 确保术语和概念与前文一致

### 第 3 步：设计文章结构

先设计骨架，不写正文。用这个框架思考：

```
问题/动机 → 为什么需要这个机制
  │
  ├─ 用数字或场景建立直觉
  │
核心概念 → 机制的全貌
  │
  ├─ 架构图或流程图
  ├─ 关键组件的职责
  │
  ├─ 分层/分步展开（从轻到重，从简单到复杂）
  │
细节/边界 → 机制的限制和代价
  │
  ├─ 什么会丢失/失效
  ├─ 与其他机制的联动
  │
延伸 → 这个机制如何融入更大的系统
```

**把结构展示给用户确认**，确保方向正确再动手写。这一步可以避免大量返工。

### 第 4 步：撰写初稿

按确认的结构写正文。写作时注意：

**开头**：用一个具体的场景或数字切入，让读者立刻知道"这章要解决什么问题"。不要用"本章将介绍..."这种教科书式开头。

**段落衔接**：每个 h2 段落的结尾应该自然引出下一个段落。读者应该感到"顺理成章"而不是"突然跳转"。

**技术细节**：
- 用表格对比（如"什么存活、什么丢失"）
- 用 ASCII 图表达结构（如上下文的三层组成）
- 用伪代码表达逻辑（如主循环中的压缩检查）
- 关键数字要准确（阈值、上限、默认值）

**结尾**：用一到两段话总结，或指向下一章/延伸阅读。不要重复正文。

### 第 5 步：验证准确性

**这是必要步骤，不可跳过。**

写完初稿后，对照源码验证文章中的每个技术细节：

- 阈值和常量值是否准确（如缓冲区大小、token 上限）
- 触发条件描述是否完整（是否有遗漏的触发机制）
- 流程描述是否与源码实际逻辑一致
- 因果关系是否正确（如"A 导致 B"是否真的在代码中是这样）

用 Explore 子代理搜索源码验证。如果发现错误或遗漏，立即修正。

### 第 6 步：润色

调用 editor-in-chief 子代理润色文章。重点关注：

- 表述是否通顺、是否有逻辑跳跃
- 段落衔接是否自然
- 技术术语是否一致
- 不改变文章结构和核心观点
- 保持作者的原有写作风格

### 第 7 步：最终确认

向用户展示最终稿，提醒用户关注：
- 是否有与前文章节矛盾的概念
- 是否有超出读者预期知识范围的内容
- 关键技术细节是否准确（已通过源码验证的部分要注明）

## 格式规范

- 每个 Markdown 页面从 h1（`#`）标题开始，且整页只有一个 h1
- h1 的内容必须与 frontmatter 中的 `title` 字段完全一致
- 页面内的章节用 h2（`##`）和小节用 h3（`###`）组织
- 图片必须使用 OSS 源，禁止使用本地图片

## agent-revelations 特定规范

当为 agent-revelations 写作时，额外遵循：

- **读者画像**：使用过 Claude Code 的程序员，了解基本用法，但不了解底层原理
- **源码位置**：`external/cc-haha/`（Claude Code 源码）、`external/claude-code-docs/docs/`（官方文档）
- **分析源码来撰写**，但文章中只讲原理，不引用代码
- **与官方文档互补**：官方文档讲"怎么用"，这里讲"为什么这样设计"
- 章节编号格式：`NN-topic-name.md`，NN 为两位数字序号
