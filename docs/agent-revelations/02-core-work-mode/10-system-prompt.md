# 系统提示词：Agent 的世界观

系统提示词是 Agent 启动时收到的第一段文字，定义了 Agent "是谁"、"怎么做事"、"用什么工具"、"怎么说话"——整个行为的底层蓝图。如果 Agent Loop 是心跳，工具系统是双手，系统提示词就是 Agent 的**世界观**：它决定了 Agent 看到什么、看不到什么、如何理解自身行为。

## 为什么系统提示词如此重要

大语言模型的每次调用都是**无状态的**——模型本身不记得上一轮对话，也不知道自己身处什么环境。系统提示词就是在每次调用前注入所有必要上下文的那段文字。

系统提示词的质量直接决定 Agent 的行为质量：
- 定义身份：Coding Agent 而非通用聊天机器人
- 规范流程：先读文件再改代码，而非凭空猜测
- 划定权限：哪些操作需用户确认，哪些可自主执行
- 约束表达：简洁回复，避免冗余

## 系统提示词的组装结构

系统提示词由多个**段落**动态拼装而成，每个段落有独立的计算逻辑和缓存策略。整体分为两大区域：

| 区域 | 内容性质 | 缓存策略 |
|------|----------|----------|
| 静态区域 | 通用行为准则，对所有用户一致 | 全局缓存，跨会话复用 |
| 动态区域 | 用户/会话/环境特定的信息 | 每次按需计算 |

两个区域之间有明确的**缓存边界**。边界之前的静态内容可全局缓存，边界之后的动态内容因人因时而变，不能跨会话缓存。

### 缓存边界的必要性

系统提示词占据大量 token，如果每次调用都完整发送，浪费带宽且增加成本。Anthropic 的**提示词缓存**机制允许前缀不变时复用缓存，只发送变化部分。

静态区域的内容对所有用户都一样，理论上可以缓存一次、所有人共享。但如果静态区域内混入用户特定信息，缓存会因用户而异，数量呈指数级增长。缓存边界将**确定不变的通用指令**与**因用户、因会话、因环境而异的内容**分离，静态部分只需缓存一份。

## 静态区域：通用行为准则

静态区域包含所有用户共享的行为指令，是 Agent 的"出厂设置"。

### 身份与安全

定义 Agent 的基本身份——交互式 Agent，帮助用户完成软件工程任务。同时包含网络安全限制，如不随意生成或猜测 URL。

### 系统机制说明

告知 Agent 所处系统的运作方式：
- 文本输出以 Markdown 格式、等宽字体展示
- 工具执行的权限模式（用户可选择不同权限级别）
- 系统提醒由系统自动注入，不代表用户意图
- 对外部来源数据保持警惕（检测提示注入攻击）
- Hook 机制：用户配置的 Shell 命令，执行结果视为用户反馈
- 上下文自动压缩：对话过长时自动摘要，突破上下文窗口限制

### 任务执行原则

静态区域中最长的段落，定义核心执行原则：
- **先读后改**：不对未读过的文件提出修改建议
- **最小变更**：修 bug 不顺便清理周围代码，加简单功能不引入额外可配置性
- **不过度设计**：不为假想的未来需求做抽象，三行相似代码好过一个过早的抽象
- **诚实报告**：测试失败就说失败，没运行验证就明确声明，不暗示成功
- **安全优先**：避免注入、XSS、SQL 注入等 OWASP Top 10 漏洞

### 操作谨慎性

根据**可逆性和影响范围**划分操作权限：
- 本地可逆操作（编辑文件、运行测试）→ 可自由执行
- 难以逆转的操作（删除分支、强制推送）→ 需确认
- 影响共享系统的操作（推送代码、发送消息）→ 需确认
- 一次授权不代表永久授权，每次独立判断

### 工具使用指导

- 优先使用专用工具而非 Shell 命令（文件读取工具优于 `cat`，文件编辑工具优于 `sed`）
- 独立的工具调用并行执行，有依赖关系的调用串行执行

### 语调与风格

不用 emoji（除非用户要求）、回复简洁、引用代码时标注文件路径和行号。

### 输出效率

根据用户类型提供差异化的简洁性指导。对外部用户强调直奔主题；对内部用户要求沟通时假设用户曾离开又回来，需帮助其重新跟上上下文。

## 动态区域：会话特定的上下文

动态区域的内容因用户、会话、环境而异，每次对话开始时重新计算。

### 环境信息

Agent 需要知道运行环境：工作目录与 Git 状态、操作系统与 Shell 类型、模型名称与版本、知识截止日期、是否在 Git Worktree 中运行。这些信息使 Agent 能做出环境感知的决策。

### 记忆系统

从持久化存储中加载用户的跨会话记忆（详见 [记忆系统：Agent 的经验本](./09-memory-system.md)），包括用户偏好、历史反馈、项目约束等，使 Agent 在新会话中也能"记住"之前的经验。

### 会话特定指导

根据当前启用的工具和功能，动态生成使用指导：
- 启用交互式提问工具 → 指导在不理解用户拒绝原因时主动询问
- 启用 Agent 工具 → 指导如何派遣子代理
- 启用技能工具 → 说明技能调用方式
- 启用验证代理 → 要求非平凡实现完成后经过独立验证

每个用户启用的工具组合不同，若放在静态区域，缓存会按工具组合产生大量变体，因此必须归入动态区域。

### 语言和输出风格

用户的语言偏好和自定义输出风格配置。

### MCP 服务器指令

MCP（Model Context Protocol）服务器可在连接时提供自身使用说明，注入到系统提示词中。由于服务器可能随时连接或断开，此段每次需重新计算。

### 草稿板和工具结果清理

根据功能开关，可能包含草稿板目录的使用说明（存放临时文件），以及旧工具结果的自动清理机制——上下文过长时只保留最近若干条工具结果。

## 段落的缓存机制

每个动态段落有两种缓存策略：

| 策略 | 行为 | 适用场景 |
|------|------|----------|
| 可缓存 | 计算一次，后续复用，直到会话清除或压缩 | 大多数段落——语言偏好、环境信息等在同一次会话中通常不变 |
| 不缓存 | 每次对话轮次都重新计算 | MCP 服务器指令——服务器可能随时连接或断开 |

不缓存策略有副作用：**每次重新计算可能产生不同内容，导致缓存失效**。因此被标记为"DANGEROUS"，仅在内容确实会随时间变化时使用。

## 多模式的提示词策略

Claude Code 根据不同运行模式选择不同的提示词构建策略，按优先级排列：

**覆盖模式（最高优先级）**。设置了覆盖提示词时（如 loop 模式），直接替换所有其他提示词。

**协调器模式**。多 Agent 协调模式下，使用包含 Worker 管理、任务协调、验证流程等指导的专门提示词。

**Agent 提示词**。当前会话有自定义 Agent 定义时使用：
- 自主工作模式下，Agent 提示词**追加**在默认提示词之后——保留通用能力的同时增加专业领域知识
- 普通模式下，Agent 提示词**替换**默认提示词——Agent 完全以自定义身份工作

**自定义提示词**。通过命令行参数指定的自定义系统提示词。

**默认提示词**。标准的静态+动态组合。

**自主模式**是特殊变体——Agent 完全自主运行时，系统提示词大幅简化，只保留核心身份、安全指令、记忆、环境信息和自主工作指导，去掉工具使用细节和语调指导。

### 子代理的提示词

子代理获得精简版提示词：通用 Agent 身份声明、子代理行为约束（如必须使用绝对路径、避免 emoji）、环境信息、可选的技能发现指导。精简设计减少 token 消耗，并让子代理聚焦于任务本身而非复杂的交互规范。

## 设计哲学

**模块化**。每个段落独立计算、独立缓存、独立管理。新增功能只需添加段落，无需修改整体结构。

**性能意识**。静态/动态分离、缓存边界、段落级缓存策略——所有设计都在优化：在保证功能完整的前提下，最小化每次 API 调用的 token 消耗。

**渐进式复杂度**。普通模式提供完整指导，自主模式精简到核心指令，子代理进一步精简。复杂度与场景匹配。

**条件分支**。大量功能通过条件开关控制——功能是否启用、工具是否可用、模式是否激活。同一段代码在不同配置下产生不同的系统提示词。
